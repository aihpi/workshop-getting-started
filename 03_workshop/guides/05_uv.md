# UV — Python package manager

> **Section 5 / 8** · **~15 min** · *applies to: all participants*

UV is the tool we'll use to install Python libraries and manage project environments. It's the modern, fast successor to a stack of older Python tooling.

## What is it?

A **package manager** installs and updates external libraries (other people's code) into your project. Python's traditional answer is `pip`. **UV**, built by Astral, does the same job — plus virtual environments, lockfiles, Python version management — in a single fast tool.

In this workshop we'll use UV for three things:

1. Creating an isolated Python environment for the project (so installing one library doesn't break another project).
2. Installing libraries (e.g. Jupyter, an HTTP client, an AI library).
3. Recording exact dependency versions in a lockfile so anyone else can reproduce your setup.

## Why do we use it?

Python's packaging story has been famously messy. Several tools each solve a slice of it:

| Tool | What it does | Why we don't use it |
|---|---|---|
| **pip** | installs packages | no env management, no lockfile, slow on big installs |
| **virtualenv / venv** | creates isolated environments | doesn't manage packages or Python versions |
| **conda** | env + package manager, cross-language | heavy, slow, separate package universe; overkill for pure Python |
| **poetry** | env + packages + lockfile | slower than UV, more rigid |
| **UV** | env + packages + lockfile + Python versions | the modern one-tool answer |

UV is written in Rust, so it's roughly 10–100× faster than pip on big installs. It reads the standard `pyproject.toml`, so projects stay portable. We pick it because it covers everything you need with one binary, and it's quickly becoming the default in the Python ecosystem.

## Try it

In an empty folder:

```bash
uv init demo
cd demo
uv add requests
uv run python -c "import requests; print(requests.__version__)"
```

What just happened:

- `uv init demo` created a project folder with a `pyproject.toml`.
- `uv add requests` created a `.venv/`, installed the `requests` library, and wrote a `uv.lock` file pinning the exact version.
- `uv run …` executed Python *inside* that environment.

Take a look at the generated files: `pyproject.toml` describes the project, `uv.lock` is the exact dependency snapshot, `.venv/` is the isolated environment.

## In this repository

The workshop repository already has a `pyproject.toml` and `uv.lock`. From the repo root:

```bash

```
